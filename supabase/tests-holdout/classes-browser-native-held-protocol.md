## Member schedule and truthful booking

1. Open Classes from Home at web widths 390 and 1440 and Android. Today is selected in the session branch timezone; next bookable class is visible without scrolling at 390. Show service, time, trainer, branch and real spots left. Select a different day: no results uses exactly “Nothing is scheduled on this day.” The entire empty horizon names businessNouns classes and asks the front desk when the timetable goes up.
2. Supply open one-seat, full, closed, cancelled, membership-needed and own-booked fixtures. Require dot plus the actual status word, singular “1 spot left”, plural real count and explicit “Full”; colour alone fails. Own past outcomes read Attended, Missed or Ended according to the frozen member contract. Desk unmarked ended booked rows must say “Not marked”, never auto-no-show.
3. Use membership fixtures active and frozen (both bookable), pending, expired and cancelled (not live), null start/end (open), exact inclusive start/end session-local dates and the day immediately outside each. Account status and membership status are distinct. The authoritative SQL holdout proves null/boundary parity; this app protocol confirms no contrary frozen-membership explanation or UI gate is added.
4. Book with at most three taps from tab and zero typing. Confirm sheet states the absolute local cancellation deadline before commitment. Use branch zones Pacific/Kiritimati and America/Adak, sessions crossing local midnight, DST spring gap/fall overlap; show the returned branch timezone rather than device timezone. Capture deadline instant and displayed date/time. Cancellation is available at exact cutoff and immediately before; immediately after it show the closed-window explanation in place of the action. Repeat with windows 0, 2 and 168, changing setting after initial read; command refusal must replace stale action honestly.
5. Cancel in at most three taps. Rebook cancelled_by_member and verify the same booking id and updated truthful state; cancelled_by_gym cannot be revived by the member. Replay booking returns already_booked rather than second success; replay cancel returns booking_not_cancellable. Force an interrupted response: re-read before claiming success, then explicit retry. A last-seat conflict must use exact class_full text and refresh counts.
6. Disconnect with loaded schedule: retain visibly stale facts, disable Book and Cancel, show the exact offline refusal. Reconnect produces no automatic mutation or queued retry. Repeat while a request is in flight and after background/resume; display no final optimistic success.

## Desk, rules, services and notices

10. Desk opens today's branch session roster within two taps; add a searched member within three after search. Roster shows name/code, explicit booking status, Checked in hint only from real check-in, No live membership and No app flags. Staff may read all gym rosters; trainer marking only their assigned sessions. Mark attended in one tap, no-show explicitly, undo explicitly. Cancelled session roster is read-only. No booking/cancel/mark creates check-in, attendance, no-show case, follow-up or streak input. An unmarked ended booking stays “Not marked”.
11. Owner/manager catalogue create/edit changes exactly name, description, default duration, capacity, sort order. Audit service.updated admits only changed keys among those five; activation uses its separate action. Defaults do not mutate existing sessions/rules. Disable confirmation states existing commitments continue and nothing new can be booked. Existing own bookings on disabled service remain visible and cancellable inside the window; other members see no new offer. Front desk/trainer admin URLs use existing not-found state.
12. Exercise rule creation and one-off creation/edit at 00:00 and 23:59: the requested local start day is preserved. Enter 24:00: reject without changing any rule, session or booking; actor validation still precedes body validation. A valid session ending across midnight remains attached to its start day. Generator/date-preservation proof stays with the independent SQL suite. Weekly rule identity (service/branch/weekday/start) cannot be edited: end and create instead. Editable fields state occurrence scope; result reports actual created, updated, removed, kept-because-booked counts. Individually customised sessions remain unchanged, booked commitments survive disable/end/holiday, capacity below booked floors spots at zero. Clearly distinguish one-off creation. Display timezone fallback used, inactive trainer/service, holiday and advisory overlap; overlap must not cause GL096.
13. Explicit session cancellation requires trimmed reason and real number of booked people who will be told. Result reports bookingsCancelled, noticesWritten, noticesWithheld and membersWithoutApp independently, with those without app to phone; never call in-app notices push/SMS or delivered/read. Verify affected booked status session_cancelled, attended/no_show retained, same-transaction notice rollback and dedupe with SQL evidence. Member inbox shows class_update body regardless of service/marketing consent for eligible recipients; cancelled/blocked/erased are withheld. Unlinked members still receive stored row and honest no-app count. Cancellation is not regenerated.
