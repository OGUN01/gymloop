# SHP / MEDIA independent interactive acceptance protocol

Frozen sources: shop/proposal.md, batch-2 shared/decisions/media-verification/r2-cors amendments and docs/design/v2/shp-bar.md. Written implementation-blind. This is a protocol, not executed evidence. No screenshots, browser/device results, live bucket or database acceptance are claimed.

Use the existing demo-role accounts through the mounted application. Use owner-approved isolated test data, never an arbitrary production member or object. Record role, tenant, current route, theme, viewport/text scale, action, observed text and screenshot; redact personal fields and all temporary URLs, bearer tokens and object paths. Capture each actual control's accessible name; do not invent component props or a simulated UI. Compare to SHP-Q1..Q10 separately, then give a fresh critic the screenshots and fetched references without implementation history.

## Console, categories and preview

1. Owner and manager open `/shop`; front desk is redirected to `/shop/reservations`. Trainer sees the pinned permission-denied state and no navigation link. Owner support-preview sees the actual list without photo/category/save/sell/cancel/add/reorder controls. Probe direct routes and API mutation: preview must still refuse.
2. Create one active product, one inactive product, an out-of-stock product, an incomplete-terms product, a service and a PT package through the existing add-ons editor. Shop rows show thumbnail or placeholder, name, section, category, exact price, stock, held quantity, and On sale / Hidden / Out of stock / Incomplete terms as applicable. PT package never appears. Edit terms navigates to the existing editor; Shop offers no price/stock/description/terms edit controls. Load another keyset page with tied timestamps and verify no duplicates or missing rows.
3. Open `/shop/categories`: empty pinned text; create a trimmed name; duplicate name refusal; rename; move down and up; reload to prove persisted exact order; archive and restore. Archived category products become uncategorised last on member read. Services remain flat. Drive pending, saved, failed and retry on reorder; offline disables writes. Front desk and trainer cannot access admin actions. Names are plain text, including HTML-shaped input.
4. Photo and category uses full replace: null category unassigns; null image removes. Choose a small supported file: chosen preview -> one Save -> named Uploading -> Verifying -> Saving -> Saved. No separate upload confirmation button. Force each too-large/wrong-type/upload-failed/verification-rejected/asset-in-use/rate-limited/offline state, with retry where promised. Image failure leaves placeholder and real accessible item text.

## Member list, detail and reservations

5. Use the actual member Shop destination after IA integration. Open reservations first; category groups preserve server order with uncategorised last; Other services follows. Every tile has real name, image-or-placeholder, exact price and availability dot plus word. Tile image alt is empty; placeholder aria-hidden. No exact stock, held count, staff UUID, raw media metadata or other member information appears in visible/accessibility output or response JSON.
6. Starting at list, count actual taps: item -> Reserve -> confirm, at most three. Detail shows plain text description, validity, cancellation terms and stored GST wording (2.5%, 18%, zero absent), without computed tax/inclusive/plus wording. Product quantity caps at server available quantity and 10; services stay 1; out-of-stock cannot reserve and gives a reason. Confirmation states held-until in gym timezone, desk payment and literal nothing charged in app before tap. Refuse mismatched fresh quote and sold-out conditions: pinned copy plus refreshed catalogue, never silent old-price retry.
7. On successful reservation show Reserved and held-until. Cancel in sheet, then Cancelled. Gym cancellation requires labelled Reason (shown to the member), 3..200 trimmed characters, then Cancelled by the gym with that reason. Separately reach Expired and Collected; none uses purchase/order/paid. Terms-changed note shows pinned sentence. Web failed load shows error + Retry, never mobile cache. Empty/loading/error/truncated states use pinned copy, including first-200 notice.
8. Desk Open/Closed lists show recorded price separately from current changed price and Price changed since reserved. Sell this panel uses ordinary cash/UPI/card/bank transfer; free price needs reason. Simulate retry after an ambiguous response: same panel idempotency key reused, one ordinary sale/receipt and Collected reservation. Insufficient stock states Not enough stock to sell this. Cancel the reservation and tell the member. Show expiry/not-open/quote-changed refusal; refresh quote before sale. Never change stored original reservation price or take payment in member UI.

## Browser upload and immutable publication (requires approved deployment)

9. From actual production-origin browser upload a JPEG/PNG/WebP below/equal 2 MiB with only Content-Type header. Verify browser preflight allows production PUT and no foreign origin/DELETE. Check real upload URL targets staging and expires in 300 s; captured report stores no URL. Confirm function authenticates original caller and finalizer is service-only. Direct authenticated old-confirm/finalize attempts refuse. No new media success is claimed merely from CORS passing.
10. Against approved test objects, pause upload verification between HEAD, conditional ranged GET and conditional copy; replace source, expect upload_changed and no finalized publication. Bad magic/length/MIME refuse and no confirmation. Verify live R2 conditional CopySourceIfMatch, post-copy size/MIME/magic and embedded-error handling. Simulate destination collision and prove fresh destination retry rather than overwrite. Reuse live staging PUT after publication and prove current signed GET still returns original published bytes; replay never recopies changed staging.
11. Run two verifiers on one asset with barriers around finalizer: one winner, one false loser, one audit, distinct published candidates. Lose/delete/revoke actor before finalize, then verify no success. Inject unknown finalizer outcome followed by unconfirmed or failed reread: no candidate deletion. When authoritative same candidate won retain it; a definitively completed losing finalizer cleans only its proven-unreferenced candidate. Keep records of object-only cleanup without private metadata in logs.
12. Product/trainer/announcement signer accepts only current exposed image asset under original member JWT, matching actual parent and private verified namespace. Withdraw listing/live version/promotion consent between first exposure and private lookup: second exposure refuses before GET issuance. Wrong parent, foreign tenant, unknown/unattached/unconfirmed/deleted id all produce asset_not_found. Trainer attachment uses both fixed MD5 vectors and uppercase UUID normalization, never actual UUID comparison; wrong trainer-key/image pair refuses. Previously issued GET may remain valid within <=900 s; no instant-revocation claim.

## Native device, identity and accessibility

13. On owner-operated physical Android, hot-reload mounted Shop then perform list/detail/three-tap reserve/cancel sheets. Load good catalogue online, lose network, and show last-good exact snapshot with Saved time and pinned offline sentence. Both reserve and cancel disabled and zero mutations queued; returning online refreshes before allowing mutation. Uncached image uses placeholder. Failed fetch retains only valid previous snapshot, never malformed payload.
14. Sign out then sign in as a different member of same gym; then a member of another gym. Verify cached old member reservations/images vanish immediately and never reappear offline. Test user, tenant and member changes separately. Restart app offline: in-memory cache absent; no persisted snapshot invented. Review cache clearing integration beside existing check-in queue reset.
15. Repeat mounted console/member web at 1440 px and member mobile layout at 390 px, both light/dark, 200% text and reduced motion. Inspect no clipped prices/status/hold notice/reason, logical keyboard focus, sheet dismissal and focus return, labelled reorder/quantity controls, disabled explanations and 44 px touch targets. Run actual axe on web routes/states; separately inspect native accessibility with TalkBack. Use Chalkline cl-* and existing native kit. Record every gate-30 state separately; an SSR string test does not substitute for interactive/device proof.

Acceptance remains pending until every relevant row has actual recorded observations, live trusted-media proof, and fresh-context critic comparison. SQL independent tests cover database policy/grants/invariant/history contracts; this protocol does not execute or replace them.
