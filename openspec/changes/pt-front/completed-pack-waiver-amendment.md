# Approved owner amendment — last-session late-cancel waiver

**Owner approved 2026-10-02; folded into the frozen PTF build contract before authors start.** This is a reviewable amendment to PTF-014, PTF-016, PTF-023, PTF-024 and ADR-182(6). PTF-016 now includes the scoped completed-pack exception; the orchestrator owns the corresponding domain-rule and central ADR integration. No production, tests or holdout files are changed by this document.

## Decision and concrete example

The owner approved allowing owner/manager to restore the last session forfeited by a member's late cancellation, even when that exact cancellation made the pack completed. For a ten-session pack with nine sessions used, a late cancellation uses session ten and completes the pack. An eligible waiver restores the count to nine and the status to active; the cancelled session remains cancelled and the member books a new time within the original validity. The waiver charges and refunds nothing.

Rejected alternative: retain PTF-016's current completed-pack GL055 refusal. Then owner/manager waiver is unavailable once a late cancellation exhausts the pack. The console must say this explicitly; the owner permission is qualified accordingly. Neither choice changes `pt_late_cancel_consumes_session` default true or the owner-approved no-show gap (zero consumption).

## Fixed approved names and eligibility evidence

No new RPC, route, enum or SQLSTATE. Reuse `public.waive_pt_forfeit(p_session_id uuid,p_reason text)` and its existing return shape, role checks, audit and notice. Approved provenance column `pt_cancellations.completed_order boolean not null default false`, immutable after insertion, with `pt_cancellations_completed_order_chk`: true implies member outcome, late, policy-consumes and consumed. It is true only when that cancellation's locked transaction sees an active PT order with `sessions_used = sessions_total - 1`, consumes exactly one, and changes that same order to completed. It is never inferred from timestamps or the current counter. Existing rows default false and cannot be retroactively marked.

Approved transaction-local setting `app.pt_completed_waive_command` = `waive:<session_id>:<order_id>`. No client input controls this setting. It is set only by the postgres-owned waiver definer after all checks and cleared before returning. This is an additional named Phase 6 exception to `app.enforce_addon_order()`, beyond the already accepted reassignment shape; approval of the existing three replacements does not approve this additional shape.

## Exact approved EARS amendments

- **PTF-014 amendment (completion provenance).** WHEN a member late cancellation consumes the last remaining session of an active PT pack THE SYSTEM SHALL, under the existing session and order locks in one transaction, record `completed_order = true` on its cancellation row and complete the order; every other cancellation SHALL record false. The field SHALL remain immutable through waiver and all later commands. The invariant `sessions_used = completed sessions + consumed cancellations without a waiver` SHALL continue to hold.
- **PTF-016 replacement (waiver).** WHEN a complete real owner or manager calls `waive_pt_forfeit` for a same-tenant consumed member late cancellation with a trimmed reason of 3–200 characters THE SYSTEM SHALL take the session advisory lock, then order advisory lock, then order/session/cancellation row locks in the existing PTF order, and revalidate under those locks. An active order follows the existing waiver rule. A completed order SHALL be eligible only when its cancellation has `completed_order = true`, `was_late`, `policy_consumes`, `consumed = true`, no waiver, the session remains cancelled, the keys/member/trainer match the order and provenance, the PT order has `sessions_used = sessions_total`, no scheduled reservation remains, and the original validity includes the current command's gym-local day. An expired, refunded, fully returned or partially returned pack SHALL be refused GL055 `order_unavailable`; any recorded return for this order excludes the completed-pack exception. Missing/null validity excludes it. Ordinary completed packs or completions caused by attendance SHALL be refused GL055 unchanged. An eligible completed-pack waiver SHALL decrement used by exactly one, set all three existing waiver fields, change completed → active, and write the existing waiver audit/notice atomically. The session's status/identity/time and the cancellation's consumed/policy/provenance fields SHALL stay unchanged. Refusal SHALL write nothing.
- **PTF-016 replay clause.** WHEN the same authorised waiver request is repeated after its waiver fields exist THE SYSTEM SHALL return the current used count with `replayed = true` and write no second count, audit or notice, even if the pack has since expired or completed again; replay SHALL follow full identity, same-tenant visibility and valid-input checks and precede current eligibility checks. A different valid reason SHALL not replace the recorded reason; the existing idempotent replay behaviour remains.
- **PTF-023 additional named guard exception.** WHEN `app.enforce_addon_order()` receives the completed → active update THE SYSTEM SHALL admit it only from `current_user = 'postgres'`, with `app.pt_completed_waive_command` identifying the exact cancellation/session/order, a complete active owner/manager identity with no member or impersonation claim, and an already recorded same-transaction waiver whose actor matches that identity and whose immutable `completed_order` marker is true. It SHALL admit only `status`, `sessions_used` changing by exactly minus one, and ordinary `updated_at`; tenant/member/product/trainer/currency/price/GST/sale snapshot/quantity/session total/start/expiry and every other sold term SHALL be unchanged. The guard SHALL revalidate the pre-change order through OLD: `OLD.status = completed`, `OLD.sessions_used = OLD.sessions_total`; the post-change shape through NEW: `NEW.status = active`, `NEW.sessions_used = OLD.sessions_used - 1 = NEW.sessions_total - 1`. It SHALL verify the already written waiver fields belong to this exact transaction and command actor/session/order, preserve the marker, and revalidate validity, no return and no scheduled reservation. It SHALL NOT compare the post-update counter to sessions_total or require the already written waiver fields to be null; those are command prechecks against the locked pre-change state. No general completed → active edge is added. Forged settings under authenticated, member, trainer, front desk, support preview or service_role SHALL admit no update. Every other existing refusal/SQLSTATE/detail SHALL remain unchanged.
- **PTF-024 audit amendment.** WHEN the completed-pack exception succeeds THE SYSTEM SHALL write one existing `pt_forfeit.waived` audit attributed to the real owner/manager: before `{consumed:true,sessions_used:n,order_status:'completed'}`, after `{consumed:false,sessions_used:n-1,order_status:'active'}`, with required reason. `consumed:false` is the effective waived outcome, not a rewrite of the immutable cancellation flag. It SHALL emit one deduped existing fulfilment notice `pt_forfeit_waived` and no payment, refund or ledger entry. Failure of any step SHALL roll back all steps.

## Races, validity and guard limits

Session lock then order lock retains PTF's canonical subset ordering; no trainer lock is added by a capacity-restoring waiver. Other same-order completion/refund/expiry paths must use the existing order lock. The waiver evaluates a fresh command clock after acquiring its locks, in the order's existing gym-local validity rules; validity is never extended. If expiry or a return wins first, revalidation refuses. If waiver wins first, a later expiry applies normally; a later completion rechecks the restored counter and may complete only through the ordinary legal rule. Two concurrent waivers of the same cancellation produce one restoration and one replay; two distinct completed-order claims cannot bypass the immutable causal marker or the locked exact counter. All pre-existing identity, tenant, guard and sold-term invariants remain mandatory.
