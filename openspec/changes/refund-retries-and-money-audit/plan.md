# Refund retries and financial audit

Authorized under ADR-111. The fixed EARS contract is in
`specs/refund-retries-and-money-audit/spec.md`; its normative API, comparisons,
actor rules and refusal table are frozen in
`docs/planning/refund-contract-detail.md`. No product decisions remain pending.

The comparable reference is Stripe's idempotent-request contract:
https://docs.stripe.com/api/idempotent_requests . Gymloop applies the explicit
contract below to its own manual refund ledger; no provider request is added.

One unit covers refund request identity, ordered existing financial refusals,
and the existing INT-003 financial audit requirement. Separate visible and
holdout authors work before implementation. They may inspect prior specs and
their own suite, but not implementation or each other's tests. A fresh critic
reviews the candidate without either suite. The implementer never reads holdout.

CI applies migrations, then the CLI generates public database types. Database
verification stays serialized and wrapped in rollback transactions. Prepare
tests during the preceding net-price CI run; execute them only after it ends.
