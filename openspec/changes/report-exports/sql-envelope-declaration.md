# RPE public SQL envelope — frozen mechanical declaration
Frozen 2026-10-04 after independent public-contract review and before authors. This mechanical
completion preserves the frozen CSV-first proposal, especially RPE-004/008/009;
it does not certify deployed behavior. Invoice PDF remains deferred.

## Reuse and reachable contract

Registry searches found `export_report_snapshot`, `append_report_export_event`,
`REPORT_DATASETS`, `ReportDataset`, `ReportExportMeta`, `buildReportCsv`,
`validatePaymentMoney`, exact decimal codecs and existing money formatters.
No shared RPE request/response schema/type file was found by filename/declaration
search; the registered web metadata interface is not a shared response codec.
Reuse the existing seams; a new shared codec/type or private audit helper requires
registry search, registration and a reuse decision before implementation. Generated
DB types are regenerated by CLI, never edited. No exported symbol is added here.
Canonical real RPC (five required arguments, no defaults):
`public.export_report_snapshot(p_dataset text, p_from date, p_through date,
p_branch_id uuid, p_row_cap integer) RETURNS jsonb`.
`p_dataset` is exactly `payments|attendance|members`; null branch means all branches.
`p_row_cap` is a trusted route argument, never an HTTP input; it must be an integer
in 1…5000. The HTTP body stays exactly `{dataset,from,through,branchId?}`.
Valid dates, inclusive maximum 366 calendar days and validated gym timezone apply.
Actor validation precedes semantic validation, lookup, counting and source access.
Unknown/foreign branches have one indistinguishable unavailable refusal.
The public audited command is VOLATILE SECURITY INVOKER, empty search path, authenticated-only
EXECUTE (none for PUBLIC/anon); no service role or postgres-owned source reader.
It supports transactional prepared auditing: the registry's current `STABLE`
label is not authoritative permission to omit the write; repair that declaration.
Only audit append may elevate privileges. Original caller RLS covers all source
and joined rows; authorization never substitutes for RLS or expands any policy.

## Exact scalar success envelope

Supabase data is one JSON object, never SETOF, `[object]` or implicit paged rows.
Exactly these top-level keys are required; no extra source/profile fields:
| Key | JSON type / meaning |
|---|---|
| `export_id` | Database-generated fresh UUID string for this attempt |
| `dataset` | Validated dataset string |
| `format` | Literal `csv` |
| `generated_at_utc` | Database generation/preparation start, ISO-8601 UTC `Z` |
| `snapshot_at_utc` | Database timestamp marking the authoritative source statement snapshot |
| `source_cutoff_at_utc` | Same timestamp as `snapshot_at_utc`; never a route clock |
| `range_from`, `range_through` | Validated Gregorian `YYYY-MM-DD`, unchanged |
| `range_basis` | `created_at`, `checked_in_at` or `joined_on`, respectively |
| `timezone` | Validated named gym zone used for boundaries/local formatting |
| `range_start_utc`, `range_end_exclusive_utc` | ISO UTC `Z` instants for gym-local midnight from / day after through |
| `branch_id` | Validated same-tenant UUID string, or null |
| `branch_scope` | Literal `all` for null branch; otherwise exactly the branch UUID |
| `data_row_count` | Canonical nonnegative decimal integer string: complete matching snapshot count |
| `returned_row_count` | Canonical nonnegative decimal integer string: number in `rows` |
| `row_cap` | JSON integer equal to validated `p_row_cap` |
| `has_more` | Boolean, exactly `data_row_count > row_cap` |
| `rows` | Ordered array of the dataset row objects below, including `[]` |
The cutoff marks visibility in the real database statement snapshot, not a claim
of historical reconstruction or a substitute `created_at <= clock` predicate.
All counts, joins, range selection, rows and order derive from that ONE snapshot.
The two UTC boundaries are declared for all datasets; members still filter direct
`joined_on` dates, not converted timestamps. Invalid zones never silently fall back.
Offset transitions use each actual local midnight, not a fixed 24-hour addition.
If count exceeds cap, return `rows: []`, `returned_row_count: "0"`, `has_more: true`
and the exact count/metadata; release no file. Otherwise return every matching row,
`returned_row_count = data_row_count`, `has_more: false`. A lower transport row limit
must not truncate the scalar envelope. No continuation, offset or client paging.
An accepted bounded (count ≤ cap) result is returned only after its prepared audit
commits with the source operation. Over-cap refusals create no prepared attempt.
Failures/rollback return no successful envelope or partial source payload.

## Fixed row projection and serialization

Every row has exactly its listed keys. Required keys are never omitted. SQL null
remains JSON null and becomes a blank CSV cell, never an invented value.
| Dataset | Row keys in fixed CSV order |
|---|---|
| payments | `payment_id,member_id,member_code,current_member_name,amount_paise,amount_display,currency,status,method,created_at_utc,paid_at_utc,receipt_number` |
| attendance | `attendance_id,member_id,member_code,current_member_name,branch_id,source,checked_in_at_utc,checked_in_local,checked_out_at_utc,offline_recorded_at_utc,replayed_at_utc` |
| members | `member_id,member_code,full_name,phone,email,branch_id,status,joined_on` |
IDs are UUID strings; member/payment/event IDs are not Auth IDs. Payment `status`
and `method`, attendance `source`, member `status` use generated DB vocabularies.
Money is positive canonical decimal-text paise; never a JSON number. Required
currency is explicit nonempty text. `amount_display` is the exact existing formatter's
output for that paise/currency, never parsed back; a format-only adapter may derive
this presentation key from exact money, never reconstruct monetary facts.
Required UTC event times are ISO-8601 `Z`; optional paid/checkout/offline/replay
and receipt facts are nullable. `checked_in_local` is local ISO timestamp with
numeric offset followed by ` [<timezone>]`; joined dates are `YYYY-MM-DD`.
Member code/current name are nullable for absent/erased RLS-visible profiles.
Member roster full name/phone and branch UUID are required; email/code may be null.
Attendance branch is its stored UUID. Members exclude erased profiles entirely.
Payments/attendance survive missing profiles; current name/code stay null.
Branch filters use current member branch for payments, stored attendance branch
for attendance, current member branch for members; missing association cannot match.
Ordering is ascending `(created_at,id)`, `(checked_in_at,id)`, `(joined_on,id)`.
No totals, refund netting, extra personal fields or inferred financial facts.
CSV common leading columns remain exactly
`row_type,export_id,generated_at_utc,snapshot_at_utc,range_from,range_through,
range_basis,timezone,branch_scope,data_row_count`.
One header, one `metadata` record with empty dataset columns, then all `data` rows
repeating identical stamps. Empty exports still include header plus metadata.
Counts exclude header/metadata. Route compares final serialized data count with
DB `data_row_count`; safe conversion to the existing bounded numeric metadata
interface is permitted only after canonical validation and cap checking.
BOM, CRLF, quoting and unconditional untrusted-text apostrophe protection follow
RPE-007. Byte cap/deadline/integrity/audit failure release nothing.

## Prepared/released audit linkage

Registered public signature remains
`public.append_report_export_event(p_event text,p_export_id uuid,p_details jsonb)
RETURNS void`; authenticated EXECUTE only, empty search path, narrow audit-only
definer. Public invocation accepts ONLY `p_event = 'report_export.released'`.
Prepared creation uses metadata-only `app.report_export_preparations`:
input columns `dataset text,range_from date,range_through date,branch_id uuid,
row_cap integer`; derived columns `export_id uuid PRIMARY KEY,tenant_id uuid,
actor_user_id uuid,actor_role app_role,format text,generated_at_utc timestamptz,
snapshot_at_utc timestamptz,source_cutoff_at_utc timestamptz,range_basis text,
timezone text,range_start_utc timestamptz,range_end_exclusive_utc timestamptz,
branch_scope text,data_row_count bigint`. Derived columns have no caller defaults;
the BEFORE INSERT trigger rejects supplied non-null derived values, then fills
ALL of them (all NOT NULL). Branch alone may be null. Persist no rows/contact data.
Authenticated has INSERT on ONLY the five input columns and SELECT under RLS;
no UPDATE/DELETE or INSERT on derived columns. No PUBLIC/anon table grants.
RLS INSERT/SELECT requires tenant claim, own actor and verified active real owner;
no cross-actor/tenant SELECT. Index `(tenant_id,actor_user_id,export_id)` supports
claim/actor access; index name is `report_export_preparations_tenant_actor_export_idx`.
Prepared rows are immutable retained audit-linkage metadata,
not an export cache; abandoned rows remain truthful prepared-only attempts.
Exact trigger functions, both empty search path, no PUBLIC/anon/authenticated
EXECUTE: `app.derive_report_export_preparation() RETURNS trigger STABLE SECURITY
INVOKER` (BEFORE INSERT), then `app.audit_report_export_preparation() RETURNS
trigger VOLATILE SECURITY DEFINER` (AFTER INSERT). The respective trigger names
are `report_export_preparations_derive` and `report_export_preparations_audit`.
Migration installs both triggers;
trigger invocation requires no session EXECUTE grant. The STABLE invoker trigger
is the source-selector/validator: actor first, exact inputs, RLS sources, validated
zone/boundaries and complete count; count > cap refuses INSERT. It derives UUID,
clock stamps and attribution server-side; caller values/GUCs/calling markers are
never provenance. UUID generation does not change its source-read snapshot.
The definer receives only the validated NEW metadata, appends prepared audit and
reads no report source. Its postgres-owned body's elevation is confined to
validated audit append; it exposes no source-reading or general-writing authority.
The real RPC uses ONE containing SQL statement: materialized ordered source
projection/count under original RLS, bounded preparation INSERT from ONLY the five
inputs, and final scalar assembly with returned derived metadata. The STABLE
invoker trigger's validation/count scans inherit that containing statement's
snapshot; no independent VOLATILE scan or later statement verification is allowed.
Its count/basis/boundaries must equal the statement's source projection before
return; mismatch rolls back preparation/audit. A zero-row projection still inserts
one preparation. Over-cap takes the refusal envelope path with no INSERT/audit.
Direct table INSERT can create only a lawful bounded same-actor prepared attempt,
never an arbitrary count/stamp/event. No unaudited public row-selector RPC is added.
Register this relation, both functions/triggers and index, plus the revised public
RPC volatility/grants, before source; record the metadata-only reuse decision.
Prepared event uses `record_type = 'report_export'`, `record_id = export_id`,
`action = 'report_export.prepared'`, `before = null`, and exact `after` keys:
`export_id,dataset,format,generated_at_utc,snapshot_at_utc,source_cutoff_at_utc,
range_from,range_through,range_basis,timezone,range_start_utc,
range_end_exclusive_utc,branch_id,branch_scope,data_row_count`.
Values/types equal the successful envelope. Audit columns derive tenant, real
actor user and role from the verified current owner; no caller attribution input.
Prepared append occurs atomically before payload leaves DB, including zero rows.
Release `p_details` has exactly `{byte_count,artifact_sha256}`: byte count is a
positive canonical decimal string ≤ 8 MiB, digest exactly 64 lowercase hex chars
for complete final attachment bytes including BOM. No caller-supplied metadata.
Writer revalidates active owner/claims and finds exactly this actor/tenant's
prepared UUID, rejects absent/foreign/already released attempts, copies all prepared
`after` keys and adds these two fields. It appends `report_export.released` before
first response byte. Enforce unique `(record_type,record_id,action)` for the two RPE
audit actions (partial index `audit_log_report_export_event_unique`); conflicting
release INSERT refuses atomically, never read-then-insert alone. Register this index.
There is at most one release per prepared attempt, including
concurrent calls; every fresh download/retry obtains a fresh export UUID.
The writer can attest validated linkage, not independently verify supplied bytes;
route acceptance must prove digest/count match the offered complete artifact.
Audit failure or lost eligibility releases nothing. Prepared-only is unfinished,
released means bytes offered, never proof of device save. Existing owner audit
surface shows actor/action/time/range/count and the event distinction.
No rows, names, phone, address, GSTIN, raw JSON or file content enter audit payload.

## Acceptance and freeze boundary

Behavioral acceptance MUST call REAL `public.export_report_snapshot` with all five
arguments, original authenticated callers and real audit/route seams. No mirror
RPC, standalone reimplementation or helper-only evidence substitutes. Prove exact
counts/order/caps, source snapshot coherence, boundaries, empty files, erasure,
unsafe-size money, stale/foreign/preview refusal and atomic audit linkage.
The private app-schema relation avoids adding a directly exposed public API or
widening the canonical public table-policy matrix. Its declared tenant/actor RLS
and column grants still apply. No remaining business decision is proposed.
Independent DOCS review GO covers feasibility only, never source/runtime acceptance.
