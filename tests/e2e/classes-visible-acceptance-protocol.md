Derived only from the frozen Classes proposal, batch-2 decisions and cls-bar. Component props, cache APIs and offline injection points are not frozen. Exercise the public accessible UI instead of inventing props or exported factories. Automated suites intentionally begin red for absent public modules; an import failure is collection evidence, never evidence that the behavioral assertions ran. No DB/device run is performed by this author.

## Member booking (CLS-Q1…Q5, CLS-014…022)

1. At 390 × 844, open Classes. Today is selected. Next bookable class, time, service, trainer, branch and remaining seats are visible before scrolling. Record Tab → Book → Confirm: at most 3 taps including an optional day choice, no keyboard or typed field. Confirm sheet contains the absolute free-cancel deadline in the **branch** timezone before commitment. Successful response alone establishes Booked; status includes dot and word. Book creates no check-in or attendance mutation.
2. Choose full, cancelled, closed and membership-needed rows. Show exact status words; no enabled Book for unavailable rows. Frozen membership books successfully if its inclusive local session day is within its dates; expired membership uses the pinned refusal. Other branch is refused under default policy. Trainer display name is permitted; staff id/phone/email are absent.
3. Own held/cancelled/disabled-service history stays visible; other members' names, photos, ids, booking ids or contacts never appear in member DOM, accessibility tree, state or member read response. A disabled-service session without an own booking is absent. Gym-cancelled member booking cannot be revived by the member. Member-cancelled booking can re-book; response retains the canonical booking id and truthful spots count.
4. At exact deadline, cancellation succeeds. Immediately after, replace Cancel with the exact `cancel_window_closed` explanation and a front-desk next action; do not simply hide the affordance. Cancellation takes at most 3 taps. Repeat with changed cancel-window policy and effective branch timezone. Server refusal wins over stale displayed availability.
5. Competing last-seat requests: one success and one exact `class_full` refusal; loser refreshes counts and never reports Booked. Retry an already-booked response uses the exact copy. Verify every pinned refusal sentence from shared visible suite, including fallback; no SQLSTATE or internal error leaks.
6. Offline during book/cancel: show the exact offline sentence **before** submitting; transport is not called, no queue item/local booking is created, reconnect triggers no deferred mutation. Existing schedule can display stale data only with an explicit stale/read-only indicator. Existing connection-failure and retry states offer a real action.

## Desk and owner (CLS-Q6…Q8, CLS-001…013, CLS-023…028)

1. Desk Classes → session roster within 2 taps. Search a member then add within 3 taps. Front desk has timetable/roster and desk booking/cancellation; trainer can read roster but mark only an assigned session; owner/manager alone access catalogue, schedule, settings and session cancellation. Complete platform/support-preview identities get no mutation control or write. Cancelled roster is read-only.
2. Mark attended in 1 tap, mark no-show explicitly, undo to booked. Show checked-in information separately. An unmarked past booking says **Not marked**; no timer, check-in, render or loader marks it absent/attended. Test attended from start minus 60 minutes, no-show from start, all marks through end plus 24 hours; outside window show session-not-open. Same-status retry is truthful without a duplicate audit.
3. Create a trimmed service with defaults. Edit exactly name, description, default_duration_minutes, default_capacity and sort_order; activation is a separate control/action. Default edits change only future prefills, never existing rule/session snapshots. No-change edit produces no audit; changed-key audit has exactly those permitted fields, no is_active. This audit assertion is verified by the independent SQL author, while UI/requests demonstrate separate operations.
4. Weekly and one-off creation are clearly distinguished. Weekly form selects weekdays, branch-local start and dates; edit keeps weekday/start/service/branch identity immutable and explains ending-and-creating to move a rule. Reports exact created/updated/removed/kept-because-booked counts. Lowering capacity below holding count fails honestly. Trainer overlap is advisory, never a CLS GL096 refusal.
5. Disable service, end/deactivate rule, add holiday, deactivate trainer: UI explains freeze-and-finish; booked commitments remain without automatic cancel/notice. Individually customised sessions stay detached. Never-booked derived rows may disappear; previously cancelled/ever-booked rows are not resurrected. Re-enable and repeated generation is idempotent. DST gaps and folds follow PostgreSQL `AT TIME ZONE` resolution; generation skips only when the resolved local start belongs to another date. Rule and explicit creation/edit reject 24:00 after actor validation; 00:00 and 23:59 preserve the requested start day, including sessions ending after midnight. SQL independently proves generation and seat invariants; UI renders resulting instants, counts and zone faithfully.
6. Booked session reschedule/date/time/duration edit is refused; copy advises explicit cancel/recreate. Explicit cancellation asks a trimmed 3…200 character reason and names how many members will be told before confirmation. Result uses bookingsCancelled/noticesWritten/noticesWithheld/membersWithoutApp exactly; it names members without an app who need a call, never claims they received a notification. Retry does not duplicate notices. Eligible member with service consent disabled still sees transactional class_update inbox text. Blocked/erased/ineligible withheld counts stay honest.

## Identity cache and standing states (CLS-Q9…Q10)

On native and web, load member A's schedule, go offline, sign out, switch Auth account/member/gym identity to B, and navigate Classes. No A session or booking survives. A delayed A read resolving after B must be discarded; no stale response populates B. Repeat active refresh, erased/blocked identity, revoked staff, support-preview and no-linked-member states. Native cache is in-memory only, never persisted to offline queue. Verify logout cache clearing through existing session lifecycle; no new public cache API is assumed.

At widths 390/1440 and both Chalkline themes, repeat open/full/booked/cancelled/late-cancel, empty, loading, failure+Retry, permission and offline states. At 200% text and reduced motion, content reflows, deadlines/counts remain visible, no horizontal overflow; all booking/day/cancel/roster controls have 44px web or 48dp Android targets. Run axe for every web state. Capture dot-plus-word status and branch timezone. Native physical Android and tap/target evidence remain required; JSX/static checks cannot substitute.

Final integrator consumes CLS `MemberClassesView`/`ClassesPane` inside PTF-owned Classes | Training controls. Verify five member tabs Home · Classes · Shop · Activity · You, Gym from Home/You, no duplicate PT/Shop surfaces; desk Classes after Check-in.
